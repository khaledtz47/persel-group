# Persel rebuild working instructions

This is a new Persel Group rebuild. Use only supplied project sources and decisions recorded here. Do not carry over content, branding, metrics, people, preferences or architecture from other clients or earlier builds.

Read content-brief.md and design-direction.md before implementation. Latest explicit user instructions take precedence. The Persel strategy controls content and audience flow; the Persel site supplies verified existing facts/assets; Vanta controls visual inspiration only.

List active global and repository instruction files at the start. Flag stale/conflicting project assumptions. Preserve the existing build; use a separate project or branch for changes. Do not delete files or replace existing architecture merely to clear context.

Font families: Fraunces headings, Work Sans body/UI. Inspect available font files and actual weights before setup. Preserve the supplied Persel logo.

Do not invent testimonials, client logos, team members, service inclusions, metrics or legal text. Separate proposed copy from source facts. No em dashes in authored copy.

Start with the homepage. Implement the strategy's two audience paths before presenting service details. Separate audience pages are approved: "I'm Hiring" links to /hiring and "I'm an Executive" links to /executives. Keep these paths visible in navigation and closing actions. Detailed service routes remain proposals. Do not substitute homepage tabs or automatic personalization.

Use the existing authorized stack if one exists. Otherwise propose a suitable stack before scaffold; avoid adding CMS/backend features without a requirement. Inspect the repository and assets before making stack assumptions.

Use semantic HTML, keyboard-accessible controls, responsive imagery, visible focus and reduced-motion support. Keep design tokens centralized and reusable. Do not report form success without a real successful submission.

Review rendered desktop/mobile screenshots, navigation, audience destinations and relevant build checks. Report completed work, validation and specific remaining blockers. Do not deploy or merge without explicit authorization.
